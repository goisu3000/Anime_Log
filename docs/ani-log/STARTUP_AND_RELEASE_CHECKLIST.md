## 作業開始前（読み取りのみ）

- [ ] **正本**：ユーザーが指定した最新版ソース、公開GitHubコミット、Vercel Productionを混同していないか。最新mainとの予想外の差分はないか。

- [ ] **設計**：正式デザインガイドの共通ルールと意図した例外に照らしているか。古いUI決定を独断で変えていないか。

## 削除・配信除外の判断

- [ ] 直接・間接import、動的読込、HTML/JS/CSS参照、移行・復元・試験で必要ないと確認したか。
- [ ] 本番配信と開発保管を分けたか。開発用ファイルを残してよくても、本番から除外可能な場合がある。
- [ ] 復元用の原本・コミット・SHAと、消す対象の明示リストがあるか。
- [ ] 削除または除外することの具体的な効果を説明できるか。
- [ ] 根拠が不十分なら**維持・保留**を選んだか。

## 実装から公開まで

- [ ] 変更ファイルは承認範囲のみで、保存・暗号化WAL・同期エンジンに予期しない差分がないか。
- [ ] 既存テストを再利用し、関連画面のPC・必要なSafari、通常/暗号化、`#share=`、履歴、QR入口などのうち影響する部分を検証したか。
- [ ] 未検証をPASSと報告していないか。性能改善を実測せずに断言していないか。
- [ ] 公開対象には製品資産のみが含まれ、テストHTML・監査資料・資格情報・バックアップが入っていないか。
- [ ] **本番公開には別途承認**があり、復帰先と停止条件を明示したか。
