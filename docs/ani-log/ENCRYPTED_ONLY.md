# 暗号化保存への製品一本化（2026-11-07・公開前候補）

ユーザー承認：旧ユーザー向けの配慮・移行UIは廃止する。現在の暗号化データ、バックアップ、同期に必要な互換処理は維持する。

- 製品UIは `index.html` 内の暗号化UIのみ。旧localStorage保存UIへのフォールバックはない。
- 製品起動モジュールは `client/formal-simple-page.mjs`。開発用の旧移行入口は製品から除外。
- 新規端末はサーバー登録なしで暗号化ローカル保存を初期化する。同期は明示的な開始操作または正規QR接続で開始する。
- 新規初期化の設定票はv2。バックアップ保存済み・旧タブ終了済みなどの移行確認を捏造しない。
- 既存端末のv1設定票、`legacy`というプロフィールID、鍵、IndexedDB名、AAD、WAL形式は変更しない。
- 古い名前のモジュールでも、現在のWAL認証・バックアップ読込み・プロフィール切替に必要なら保持する。
- 未識別の平文記録や孤立した既存WALを新規領域とみなさず停止する。自動取り込み・初期化・削除はしない。
- 新規初期化の独立認証読戻し、同時起動の排他、通常保存、バックアップ、同期checkpointの安全条件を維持する。
- 実機HTTPS起動、正規QR接続、実同期の検証はNodeの模擬DOM/IndexedDB試験と区別する。

今回の整理を理由に、削除履歴、lineage、checkpoint、Undo、WAL整理の排他・復旧アンカー・認証条件を削らない。
過去の資料にある「通常保存と暗号化保存の両UIを維持」は、この候補の正式導入後には適用しない。データ形式の互換性とは別問題である。
