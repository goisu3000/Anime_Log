## 1. 最優先ルールと作業権限

1. **現在の正常動作とユーザーデータを保護する。** 暗号化WAL、視聴記録、削除履歴、未送信変更、端末登録、同期の整合性が最優先。
2. **改善する必要がないものは改善しない。** クリーンアップは削除件数やコード行数を成果指標にしない。
3. **調査と変更を分離する。** 読み取り専用調査は可能だが、製品ファイルの変更・削除・移動・統合は、対象と根拠を提示して承認後に実施。
4. **外部の状態変更は必ず別途承認する。** GitHub push、Vercel Preview／本番配備、Cloudflare Worker／D1／KV／Secret／Route、同期端末登録の作成・失効、実データ変更などは、当該作業の範囲とリスクを明示してから。
5. **不可逆処理は原則行わない。** 原本と復帰先が保全されない状態での削除、再封印、同期解除、データ移行、強制上書きをしない。
6. **未検証をPASSにしない。** 試験環境・使用データ・実測値・未完了項目を明記し、異常時はSTOPする。
7. **ユーザー手動作業とCodex消費を最小化する。** ChatGPTがソース監査・資料・局所実装・可能な自動試験を担当し、実Windows／実ブラウザ／実機／配備権限が必要な部分のみ適切な作業者に依頼。

## 4. クリーンアップの分類と削除判定

ファイル・コード・CSSは、次の4分類に分ける。

| 分類 | 意味 | 行動 |
|---|---|---|
| A 現役・必須 | 本番実行、同期/保存互換、QR/履歴、通知、公開設定に必要 | **維持** |
| B 開発・保守資産 | 回帰テスト、監査資料、移行診断、復旧手順等で必要 | **別保管**。原則として本番配信から除外 |
| C 明確に不要 | 本番／テスト／移行／復旧から参照されず、保存価値なしと確認できる | **削除候補**。バックアップ・差分・試験を経て承認後削除可 |
| D 未判定 | 用途や参照の一部が不明 | **維持・保留** |

### 削除・配信除外を承認するためのチェック

1. 静的import、動的import、HTML参照、文字列生成URL、CSS/DOMセレクタ、リリース手順、ブラウザでの遅延読込を点検。
2. 保存・同期の互換コード、旧データ復元、QR登録、ロールバック、回帰テスト、開発診断に必要ないと確認。
3. Git/保管ZIP等から元の内容を復旧でき、削除前後の差分が明確。
4. 削除・配信除外によって得られる効果（配信対象縮小、事故防止、保守性など）を説明できる。効果ゼロなら無理に削除しない。
5. 関連試験と配信物確認を行い、異常時は即復帰。
6. **対象単位の承認を得る**。名前に `test-only`、`fixture`、`poc`、`staging`、`v数字` があるだけでは削除しない。

**今回の監査結論**：基準ZIPには、現時点で**削除可能と証明された製品ファイルは0**。`client/v353-browser-mixed-id-test-only.mjs`、`client/v365-reviewed-rank-test-only.mjs`、`client/v366-reviewed-create-test-only.mjs`、`client/v396-mixed-synthetic-fixture.mjs`、`client/verified-wal-cache-poc.mjs` などは参照されている。勝手に動かさない。

CSSも同様に、同一セレクタ18種、`!important` 35箇所は**候補を知るための手掛かり**であって不要認定ではない。実画面・Computed Style・画面状態の照合なしに一括統合しない。

- 製品配信には実行に必要なHTML・JS・JSON・設定・確認済みアセットだけを入れる。製品から参照されるテスト名付きファイルは、名前にかかわらず必要な製品資産として扱う。
- 監査ZIP、試験結果、テスト用HTML、診断スクリプト、鍵、パスフレーズ、実ユーザーデータ、バックアップは公開配信物に混ぜない。
- `PRODUCT_RELEASE_ALLOWLIST.json` は過去のCodex監査で使用されたが、**今回の基準ZIPには含まれない**。その所在・最新版・正当性を公開前に確認する。無い場合は推測で「除外済み」とみなさず、現行の正規デプロイ手順を確認。

## 6. 小変更の標準手順（調査から公開まで）

1. **目的を1文で定義**：何が問題で、何が改善するか。何もしない選択肢を含めて検討。
2. **正本を確認・保全**：最新main、現行本番のデプロイメント識別子、元ZIP/コミット、戻し方、既存バックアップ状況。
3. **影響範囲を決める**：ファイル、関数、API、表示画面、通常保存/暗号化、スマホ、共有、同期の関係を明記。
4. **別コピーで最小実装**：事前承認された箇所のみ変更。無関係なリファクタリングを同じリリースに混ぜない。
5. **小さな検証を先に実施**：構文、依存、既存テスト、対象機能のChrome実動作を再利用。必要なSafari/実通信試験だけ追加。
6. **差分と配信物を照合**：許可外ファイルなし、正本の更新取りこぼしなし、URL/画像/通知の404なし、危険な設定差分なし。
7. **公開を別途承認**：公開対象コミットと配備先・未検証事項・復帰先を報告してからGitHub/Vercelへ反映。
8. **公開後の最小確認**：実URLで起動・主画面・変更箇所・共有/履歴等の重要回帰を検証。異常時は復帰。
9. **結果を記録**：PASS/NO-GO/STOP、担当、バージョン、コミット、Vercelデプロイメント、変更ファイル、テスト、未検証、復帰手段。

### 変更規模に応じた最小試験の例

| 変更 | 基本確認 | 必要時追加 |
|---|---|---|
| 文書・監査資料だけ | 元ZIPの不変、記述の出典と整合 | なし |
| 文言・色・CSS一部 | 対象画面のPC/スマホ表示、選択/フォーカス、関連幅 | 通常/暗号化の状態切替、Safari |
| URL・履歴・通知・共有 | 直接URL、戻る/進む、`#share=`、404と通信件数 | Safari/BFCache、QR入口 |
| 保存・暗号化WAL・同期 | 別扱いの高リスク工程。独立復元・複数端末・障害復帰のゲートが必要 | 本番で直接実験しない |

## 7. 本番データ・同期の絶対保護

- `localStorage`、IndexedDB、暗号化WAL、チェックポイント、削除履歴、バックアップ、同期資格情報、サーバー側端末登録、Cloudflare D1を**整理目的で削除・初期化・書換えしない**。
- 保存済みの記録や未送信変更を消す可能性のある操作、QR再ペアリング、同期解除、Worker/D1の切替は明示的な個別承認が必要。
- 実データを検証に使わず、独立テスト領域と合成データで行う。実機検証が必要なときは安全な手順を示す。
- エラー時に強制的な再保存・WAL再生成・旧版タブの編集再開・自動復元をしない。原因未確定で本番コードへ安全性を装った回避策を加えない。
- 保存エンジンのコードを変えずとも、UI起動順やURL・モーダル・バックグラウンド復帰が保存動作に影響する可能性を見落とさない。
- コードのデプロイを旧版へ戻すことと、データの復元は別。ロールバック可能性を誇張しない。

## 8. Cloudflare・GitHub・Vercelでの外部操作ルール

- **通常のクリーンアップでは外部環境を変更しない**。調査時はまずローカルと読取専用の管理画面情報を使う。
- Cloudflare作業が必要ならChromeの日本語管理画面を第一候補として検討し、対象Worker/Pages/KV/D1・本番/QAを厳密に区別。承認のない作成、削除、公開経路ON、Secret変更をしない。
- GitHub `goisu3000/Anime_Log` と Vercel `anime-log-rouge.vercel.app` は既知の公開先。ただし、実際のProduction branch、最新コミット、設定値は公開直前に改めて確認する。
- 不要な新規サービス・課金・ツール連携・テストインフラを設けない。既存のテスト資産を優先して再利用。
- 本番作業をCodexに渡す場合は、一括指示に作業範囲・STOP条件・成果物・担当を明記し、ユーザーのつきっきり操作や承認往復を減らす。

## 9. STOP / GO 判定

**STOPが必要な例**：現行正本不一致、復帰先の未確保、配信リストが不明で不要ファイルが混入、保存・同期への予期しない差分、削除対象の参照元未確定、重大なテスト失敗、権限範囲外の操作、ユーザーデータ安全性が確認できない。

**GOの最低条件**：差分が承認範囲内、変更による効果が説明可能、関連検証合格、未検証項目が明記済み、復帰手段がある、公開の明示承認があること。事前検証の一部を省略して本番試験へ進める場合は、そのリスク・停止操作・バックアップ条件を明示した**個別判断**とし、恒久的な例外ルールにはしない。

既存資料と矛盾した場合は、まず**明示的な最新承認・実測・現行正本**を確認し、過去の案を勝手に上書きしない。重要な未解決点は「未確認」と記す。
