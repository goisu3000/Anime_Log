# ANI:LOG デザイン例外・現物照合台帳

**資料の性格**：2026-11-05版の設計原則とコード監査から作った**確認表**。画面上の不一致を新たに認定したものではない。実画面で問題がないなら何もしない。

| 対象 | 守る意図・現行の特徴 | 要確認となる場合 | 今回の判断 |
|---|---|---|---|
| マイリストの1列／2列 | 情報密度に応じた別レイアウト。評価・スコア・操作部品のDOMを共用できるとは限らない | カード崩れ、操作領域や表示欠落が実際に起きたとき | **維持** |
| PC／スマホの操作部品 | スマホのタップしやすさ、ネイティブ選択要素との連携、iOS入力時のズーム対策 | 実機で使いづらさ・文字切れが確認されたとき | **維持** |
| 同期ダイアログ | 通常時は簡潔、危険操作の安全説明は必要時に開示。QRや承認の順序を尊重 | 実画面で不要文言・意味の重複・余白崩れが確認されたとき | **維持・画面確認待ち** |
| ランキングの色 | ライムだけに統一せず、金銀銅や分析色の意味を守る | 誤解を招く意味色の不一致があるとき | **維持** |
| ボタンの左右配置 | スマホは原則「実行・確定」左、「閉じる・キャンセル」右。ただし危険操作は安全優先 | 同じ意味の操作が不自然に逆になっていたとき | **維持** |
| 保存・同期の状態色 | 成功・注意・失敗を色だけに頼らずアイコンと短文で表す | 状態誤認が起きるとき | **維持** |
| 軽いモーション | 操作の理解だけを補助し、`prefers-reduced-motion` に配慮 | 不要な動き・待ち・ちらつきが実機で確認されたとき | **維持** |
| CSS再定義 | 同一セレクタ18種類、うち同期関連10種類。後続CSSに意味がある可能性 | 同じ表示条件でComputed Styleを照合し、不必要な重複と証明できたとき | **一括統合しない** |

## 実画面確認を要する場合の最小記録

1. 対象画面・端末・画面幅・保存モード・状態（ダイアログ開閉、マイリスト1/2列など）
2. スクリーンショットと期待する表示・操作
3. 意図的な例外か、実際の不一致か、未判定か
4. CSSの定義順・後続ルール・メディア/コンテナ条件
5. 変更案と変更しない案、最小テスト、復帰方法
